sum 7 LLOD
  • 1. Motivation & The FAIR Principles
    • Core Problem (Pain Points)
      • Language Resources (LRs) are hindered by proprietary formats, isolated schemas, and data siloing 格式私有化，标注模式不一样，资源孤岛
      • Standardized data management marks the maturity of a scientific discipline.
    • The FAIR Principles
      • Findability
        • Assign unique, persistent identifiers (URIs) to (meta)data
      • Accessibility
        • Data must be retrievable via free, open protocols supporting authentication
      • Interoperability 互操作性
        • Use formal, standard, and accessible data models for sharing
      • Re-usability
        • Clear licensing and explicit provenance 提供清晰的许可协议和来源说明
  • 2. Linked Data (LD) & The Semantic Web
    • 4 Rules of Linked Data
      • (1) Use URIs for things; 为所有事物（如词典条目、语料库中的 Token）分配 URI - findability
      • (2) Use HTTP URIs for lookups; 允许人类和机器查找资源 - accessibility
      • (3) Use web standards (RDF, SPARQL); - interoperability
      • (4) Include links to other URIs - re-usability
    • Semantic Web (SW)
      • An extension of the Web where information is given well-defined meaning so machines and humans can cooperate
      • It relies on OWL (Web Ontology Language) to formally define vocabularies
  • 3. Resource Description Framework (RDF) & RDFS
    • RDF Basics
      • The underlying data model of LD/SW
      • A "Resource" is anything that can have a URI.
    • The Triple Structure
      • Data is represented as Subject (Resource) →\rightarrow→​​​​​​​​​​​ Predicate (Property) →\rightarrow→​​​​​​​​​​​ Object (Resource/Literal)
        • 主语：资源标识；谓语：属性或者关系；宾语：资源或字面量（Literal，如字符串、日期、数值）
    • Dual Role of Properties
      • Object Properties
        • Connect one individual resource to another individual resource.
      • Datatype Properties
        • Connect an individual resource to a literal value (strings, numbers, dates).
    • Serialization
      • The process of converting abstract triples into file formats for storage/transmission (e.g., Turtle, JSON-LD, RDF/XML, N-Triples)
    • RDF Semantics & Inference
      • Rules that allow machines to automatically calculate and infer new triples from existing data constraints.
    • RDF Schema (RDFS)
      • Adds data-modeling vocabularies such as Classes, Subclasses, Subproperties, and Domain/Range constraints (restricting what types of entities can sit at the subject and object positions).
  • 4. Interoperability & LLOD Cloud
    • Linguistic Linked Open Data (LLOD) Cloud
      • A subset of the global LOD cloud indexing linguistically relevant open datasets converted into RDF.
    • 4 Core Types of LLOD Resources
      • Corpora
        • Linguistically annotated text datasets.
      • Lexicons
        • Dictionaries providing grammatical information.
      • Term bases 术语库
        • Thesauri focusing on vocabulary and alignment rather than syntax.
      • Metadata
        • Data describing the features of languages and datasets
    • Two Levels of Interoperability:
      • Structural Interoperability
        • Ensuring data can be accessed/combined using standard formats and protocols (LD Rules 1, 2, 3)
        • 通过标准格式（RDF）和查询协议（SPARQL）确保数据集可以被访问和组合
        • it only deals with the syntax, the infrastructure, not with semantics of the interraltions
      • Conceptual Interoperability
        • Using a common vocabulary and ontologies (LD Rule 4)
        • 使用通用的词汇表和本体（如 OLiA）来统一数据类别
  • 5. Advanced Linguistic Models & Metadata
    • Ontolex-lemon
      • The standard architecture for representing lexical resources on the Semantic Web
      • It features 5 modules
        • Core
        • Syntax & Semantics
        • Decomposition
        • Variation & Translation
        • Metadata
    • Ontolex Core Chain
      • Lexical Entry (Headword/Lemma) →\rightarrow→​​​​​​​​​​​ has Lexical Form (Written representation) →\rightarrow→​​​​​​​​​​​ mapped via Lexical Sense (The bridge) →\rightarrow→​​​​​​​​​​​ to an Ontology Entity (Concept/Reference in the real world).
    • Ontolex FrAC Module
      • Extends Ontolex to handle statistical corpus data, enabling links to Corpus Frequency, Collocations, and Embeddings.
    • Metadata Models
      • General
        • DC-Terms (for titles, creators) and DCAT (for data catalogs and downloadable file distributions).
      • Linguistic Specific
        • Meta-Share.owl for fine-grained descriptions of language resources and explicit licensing modules.
  • 6. OLiA (Ontologies for Linguistic Annotation)
    • The Problem
      • Different corpora use wildly different tags for the same parts of speech (e.g., N vs Noun), hindering cross-dataset querying
    • 4-Tier Modular Architecture
      • Reference Model
        • The absolute framework defining standard concepts (e.g., olia:Noun, olia:Accusative).
      • Linking Model
        • Connects the unique annotation tags back to the universal Reference Model.
      • Annotation Models
        • Captures the specific individual tagsets used by distinct corpora.
      • External Reference Models
        • Integrates pre-existing repositories (e.g., ISOcat, GOLD).
    • Low-level constraints
      • OLiA intentionally avoids restricting property domains to stay flexible enough to accommodate various corpus annotation styles.
  • 7. Lifecycle of Publishing Linguistic Linked Data
    • Specification
      • Analyze data sources, choose data licenses, and design URI structures (Recommended pattern: http://{domain}/{type}/{concept}/{reference}) using either descriptive or opaque URIs.
    • Modelling
      • Re-use domain ontologies (Ontolex, OLiA) to ensure interoperability instead of reinventing them; build extensions with tools like Protégé.
    • Generation (ETL)
      • Map data elements (e.g., XML tag n →\rightarrow→​​​​​​​​​​​ lexinfo:noun). Convert via specific formatting tools (e.g., Open Refine for CSV, D2RQ for DBs). Validate for broken links and OWL logical inconsistencies.
    • Linking
      • Build relations to major third-party datasets and data hubs (e.g., DBpedia, BabelNet)
    • Publication
      • Host the data in a dedicated triple-store database (e.g., Apache Jena, GraphDB) and open a SPARQL endpoint
    • Exploitation
      • Build external applications that access and parse data through the endpoint
  • 8. SPARQL Keywords & Best Practices
    • SPARQL
      • W3C query language designed to query RDF graphs using graph patterns. It is strictly data-oriented and does not perform reasoning on its own.
    • Key Commands:
      • ?variable
        • A dynamic slot used to match data dynamically.
      • WHERE
        • Defines the graph pattern and filters matching data relationships out of the dataset.
      • SELECT
        • Controls exactly which variables are shown in the final output table.
      • PREFIX
        • Creates shorthand aliases for long namespace URIs.
      • FILTER
        • Restricts query results (e.g., regex(?title, "pattern", "i") for case-insensitive matching).
      • ORDER BY / COUNT / GROUP BY
        • Sorts, counts, or aggregates query variables into structured lists.
    • AI Prompting Tip: When asking GenAI to write SPARQL queries, do not use loose natural language. You must provide the exact ontology types, property connections, and target namespaces to get correct code.
